# xquic_wht 项目结构解读

本文档用于快速理解 `xquic_wht` 仓库中各目录和关键文件的用途。解读重点是当前 checkout 的实际结构：XQUIC 核心库、公共 API、mini 示例程序、GX 设备压测脚本、构建配置和第三方依赖。

配套结构图见 [项目结构图.mmd](./项目结构图.mmd)。

## 一句话定位

这是一个基于 C/CMake 的 XQUIC 项目。核心能力是 QUIC 与 HTTP/3 协议栈实现；`include/xquic` 对外暴露 API，`src` 实现协议栈，`mini` 提供客户端/服务端示例，`GX` 是本地扩展的 5G/Agg 设备压测工作流。

## 顶层目录总览

| 路径 | 类型 | 用途 |
| --- | --- | --- |
| `include/xquic/` | 公共 API | 对外暴露 XQUIC 和 HTTP/3 接口，应用侧主要包含这里的头文件。 |
| `src/` | 核心源码 | QUIC 传输层、HTTP/3、TLS 适配、拥塞控制和基础工具的实现。 |
| `mini/` | 示例/测试程序 | 构建 `mini_client` 和 `mini_server`，演示如何用 XQUIC API 发起 HTTP/3 请求和服务。 |
| `GX/` | 设备压测工作流 | 通过串口和 SSH 控制 5G 模块，远端执行 `mini_client`，生成 5G1/5G2/Agg 结果日志。 |
| `docs/` | 官方文档 | API、特性、平台、FAQ、中文文档和 RFC 翻译资料。 |
| `scripts/` | 辅助脚本 | 测试脚本、qlog 解析、clog/slog 指标分析、符号导出脚本。 |
| `interop/` | 互操作测试 | QUIC interop 使用的 Dockerfile 和 endpoint 脚本。 |
| `cmake/` | CMake 模块 | SSL、libevent、CUnit 查找模块和 iOS 工具链文件。 |
| `lib/` | 第三方依赖快照 | 当前仓库内的 x86/aarch64 第三方库源码或预编译产物，体量大，不是主线源码。 |
| `build/` | 构建产物 | 本地构建输出目录，不作为源码阅读入口。 |
| `.github/` | CI 配置 | GitHub Actions、CodeQL 等项目自动化配置。 |

## 公共 API: `include/xquic`

| 文件 | 用途 |
| --- | --- |
| `xquic.h` | XQUIC 主 API。定义 engine 类型、版本、回调、连接/流/数据包处理等核心接口。 |
| `xqc_http3.h` | HTTP/3 API。定义 H3 连接、请求、Header、回调和读写通知接口。 |
| `xquic_typedef.h` | 公共类型定义，包括连接、流、CID、时间、配置结构等基础类型。 |
| `xqc_errno.h` | 错误码定义。 |
| `xqc_configure.h` | 构建配置头文件，由 `xqc_configure.h.in` 生成或维护。 |

阅读应用如何接入 XQUIC 时，优先从 `xquic.h` 和 `xqc_http3.h` 看边界，再到 `mini/` 找调用示例。

## 核心源码: `src`

`src` 是 XQUIC 主库实现，最终被 `CMakeLists.txt` 聚合成 `xquic-static` 和 `xquic` 两个库目标。

| 目录 | 职责 |
| --- | --- |
| `src/common/` | 基础设施：日志、时间、随机数、字符串、哈希、队列、内存池、buffer、优先队列等。 |
| `src/transport/` | QUIC 传输层核心：engine、connection、client、stream、packet、frame、send/recv、CID、timer、transport params、多路径、datagram。 |
| `src/transport/scheduler/` | 多路径调度策略：minrtt、backup、balanced、act、bandwidth、rap，以及可选 interop 调度器。 |
| `src/transport/reinjection_control/` | 多路径场景下的数据重注入/重传控制策略。 |
| `src/transport/fec_schemes/` | FEC 相关编码方案，包括 XOR、Reed-Solomon、packet mask 等可选实现。 |
| `src/http3/` | HTTP/3 层：H3 连接、请求、流、Header、Frame、扩展 Datagram/Bytestream。 |
| `src/http3/qpack/` | QPACK 编解码、静态表、动态表、指令和前缀整数/字符串处理。 |
| `src/tls/` | TLS 和加密抽象：TLS 上下文、HKDF、crypto、null crypto、SSL 回调。 |
| `src/tls/boringssl/` | BoringSSL 适配实现。 |
| `src/tls/babassl/` | BabaSSL/Tongsuo 适配实现。 |
| `src/congestion_control/` | 拥塞控制算法：默认 Cubic、BBR，按选项可启用 Reno、BBR2、Copa、Unlimited。 |

核心阅读顺序建议：

1. `src/transport/xqc_engine.c`：理解 engine 主循环和包处理入口。
2. `src/transport/xqc_conn.c`：理解连接生命周期。
3. `src/transport/xqc_stream.c`：理解 QUIC stream 管理。
4. `src/http3/xqc_h3_conn.c` 与 `src/http3/xqc_h3_request.c`：理解 HTTP/3 API 到传输层的映射。
5. `src/tls/xqc_tls.c` 与对应 SSL 适配目录：理解 TLS 和加密依赖。

## 示例程序: `mini`

`mini` 是最直接的应用侧参考，也是 GX 工作流使用的 `mini_client` 逻辑来源。

| 文件 | 用途 |
| --- | --- |
| `mini/CMakeLists.txt` | 构建 `mini_client` 和 `mini_server`，链接 `xquic-static`、libevent、zlog 和依赖库。 |
| `mini/mini_client_main.c` | 客户端 main：初始化参数、创建连接上下文、执行 `xqc_mini_cli_main_process`、进入 libevent 循环。 |
| `mini/mini_client.c` | 客户端主体：创建 XQUIC client engine、初始化 H3、创建连接和请求、socket 收发、接口绑定、多路径处理。 |
| `mini/mini_client_cb.c` | 客户端回调：H3 连接/请求生命周期、读写通知、统计输出和关闭逻辑。 |
| `mini/mini_client.h` / `mini/mini_client_cb.h` | 客户端配置结构、上下文结构、函数声明。 |
| `mini/mini_server_main.c` | 服务端 main：初始化参数、创建监听连接、进入 libevent 循环。 |
| `mini/mini_server.c` | 服务端主体：创建 server engine、初始化 socket/H3、处理 UDP 包。 |
| `mini/mini_server_cb.c` | 服务端回调：请求读取、响应头/响应体发送、连接关闭、统计。 |
| `mini/common.c` / `mini/common.h` | mini 客户端/服务端共享配置、URL/方法/文件等工具逻辑。 |
| `mini/client_config.txt` | 客户端默认配置样例。 |
| `mini/server_config.txt` | 服务端默认配置样例。 |
| `mini/get1GBfile.py` | 辅助生成测试文件的脚本。 |

`mini_client` 的关键外部行为包括：

- 使用 `xqc_engine_create(XQC_ENGINE_CLIENT, ...)` 创建客户端 engine。
- 使用 `xqc_h3_ctx_init` 初始化 HTTP/3。
- 使用 `xqc_h3_connect` 建立 H3 连接。
- 使用 `xqc_h3_request_create`、`xqc_h3_request_send_headers`、`xqc_h3_request_send_body` 发请求。
- 通过 libevent 驱动 socket 读写和 `xqc_engine_main_logic`。
- 在多网卡场景下可通过 `SO_BINDTODEVICE` 绑定指定接口。

`mini_server` 的关键外部行为包括：

- 使用 `xqc_engine_create(XQC_ENGINE_SERVER, ...)` 创建服务端 engine。
- 初始化 H3 回调并绑定 UDP socket。
- 收到 UDP 包后调用 `xqc_engine_packet_process`。
- 在 H3 请求回调中读取请求并发送响应。

## GX 压测工作流: `GX`

`GX` 不是 XQUIC 主库的一部分，而是当前仓库内用于设备验证和压测的本地工作流。它把 5G 模块控制、SSH 远端执行和 `mini_client` 结果解析串起来。

| 文件/目录 | 用途 |
| --- | --- |
| `GX/stress_gx.py` | 压测总编排。初始化两个 5G 模块，按 `Agg -> 5G2 -> Agg -> 5G1` 顺序运行测试。 |
| `GX/serial_at.py` | 通过串口 AT 命令控制 5G 模块，例如打开/关闭 GPRS、检查网络状态。 |
| `GX/ssh_gx.py` | SSH 到目标设备，进入 `/oemdata/gx/xquic_file`，切换远端配置文件，执行 `./mini_client`，解析输出并写 summary 日志。 |
| `GX/mini_client` | 放在 GX 目录中的设备侧客户端二进制或拷贝产物。 |
| `GX/gx_stress_*.log` | 压测主流程日志。 |
| `GX/log*/` | 5G1/5G2/Agg 的历史 summary 日志，数量大，主要作为结果数据归档。 |
| `GX/__pycache__/` | Python 运行缓存，不是源码阅读重点。 |

GX 的核心调用链：

1. `stress_gx.py` 控制 5G1/5G2 模块上下线。
2. `stress_gx.py` 调用 `ssh_gx.single_test(mode)`。
3. `ssh_gx.py` 通过 SSH 进入远端 `/oemdata/gx/xquic_file`。
4. 按 `Agg`、`5G1`、`5G2` 和上传/下载模式切换远端 `client_config*.txt`。
5. 执行远端 `./mini_client`。
6. 从 stdout 匹配 `all streams sent` 或 `all download streams finished`。
7. 写入 `GX/log/...summary...log`。

注意：`client_config_post_5G2.txt` 和 `client_config_get_5G2.txt` 在此工作流中是远端设备配置文件，不是当前 Windows 仓库里的普通本地文件。

## 构建系统与依赖

当前 `CMakeLists.txt` 的主目标：

- `xquic-static`：静态库。
- `xquic`：动态库。
- `mini_client` / `mini_server`：只有开启 `XQC_ENABLE_TESTING` 时通过 `add_subdirectory(mini)` 构建。

主要 CMake 选项：

| 选项 | 含义 |
| --- | --- |
| `XQC_ENABLE_TESTING` | 构建 `mini` 示例程序。 |
| `XQC_ENABLE_EVENT_LOG` | 启用 event log。 |
| `XQC_SUPPORT_SENDMMSG_BUILD` | 启用 sendmmsg 支持宏。 |
| `XQC_ENABLE_FEC` | 启用 FEC 框架。 |
| `XQC_ENABLE_XOR` / `XQC_ENABLE_RSC` / `XQC_ENABLE_PKM` | 启用具体 FEC scheme。 |
| `XQC_ENABLE_RENO` / `XQC_ENABLE_BBR2` / `XQC_ENABLE_COPA` / `XQC_ENABLE_UNLIMITED` | 启用额外拥塞控制算法。 |
| `XQC_ENABLE_MP_INTEROP` | 启用 MPQUIC interop 调度器。 |

构建注意事项：

- 当前 `CMakeLists.txt` 顶部写死了 Linux/aarch64 交叉编译器和 `/opt/crosstools/sysroot`。
- `SSL_TYPE` 默认是 `babassl`。
- CMake 中引用的 SSL/libevent 路径是 `third_party/...`，但当前 checkout 顶层实际能看到的是 `lib/aarch64` 和 `lib/x86`。如果直接构建失败，应先核对第三方依赖目录是否按 CMake 预期放置。
- `build.sh` 会删除并重建 `build/`，属于构建操作，不是本文档生成过程需要执行的步骤。

## 不建议逐文件阅读的目录

| 路径 | 原因 | 建议处理方式 |
| --- | --- | --- |
| `lib/` | 第三方库体量非常大，包含源码、对象文件和预编译产物。 | 只在排查依赖或链接问题时进入。 |
| `build/` | 构建产物目录。 | 可删除重建，不作为源码阅读入口。 |
| `GX/log*/` | 历史测试结果数量大。 | 只有做具体压测故障分析时按时间和模式筛选。 |
| `GX/__pycache__/` | Python 缓存。 | 忽略。 |
