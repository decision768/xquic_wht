# 压测脚本稳定性审查

日期：2026-11-04。审查对象为 `test_wht/压测（路测+裘博指标）.py` 和同目录 `roadtest_observability.py`。

## 本次故障与修复

第五轮 adaptive Agg POST 成功传输 104857600 字节。发送端 path 1 在接口登记前出现一条 `control_update`：映射版本为 1、接口名为空。10.156 毫秒后的记录已登记为 `usb0`、映射版本为 2。两个稳定映射的覆盖率都是 100%，初始化映射只有一个时间点，覆盖率为 null，原验收规则因此终止实验。

修复在 `_summarize_windows` 中识别有充分证据的初始化单点。必须同时满足：这是该连接、该路径最早观察到的映射；仅一个采样点；接口名为空；版本号有效；记录和校验有效；后续更高版本具有同一非空本地及对端地址、已登记接口名和非零观测时长；映射交接间隔不超过采样周期的 2.5 倍。

这些记录保留在原始数据、path_windows 和汇总中，覆盖率仍为 null，标记 `coverage_applicable=false`、`coverage_reason=initial_interface_mapping_singleton`，不会伪造为 100%。稳定路径仍须满足 99% 的覆盖率门槛。孤立单点、实际采样缺口、已有映射后的未知映射、地址改变、校验错误等情况继续验收失败。

## 流程审查

| 环节 | 当前保护 | 审查结果 |
| --- | --- | --- |
| 启动预检 | 检查源文件、算法参数支持、接口路由、空间及旧客户端；服务端核对端口和实际算法 | 有明确失败反馈；启动响应丢失仍有恢复限制，见下表 |
| 传输 | 命令超时、原始 stdout/stderr 保存、传输结果及字节数核对、可选 SHA256 | 业务结果与观测结果分别保存 |
| 观测 | 双端检查点、原始文件 SHA256、序列与健康状态、流范围及 HoL 对账 | 真实缺失仍终止；本次初始化误判已修复 |
| 清单落盘 | 临时文件写入、flush/fsync、原子替换、Windows 有限重试 | 重试耗尽仍报错并保留旧清单 |
| 收尾 | finally、独立执行各清理步骤、停止写入进程后按会话清单删除、删除后验证 | 一个步骤失败不会跳过全部收尾；永久断连或强制杀进程不能保证即时清空 |
| 再次启动 | 根据同主机、同目录绑定的旧会话清单恢复；检查活动进程与控制机锁 | 优先防止误删其他运行任务，不会盲目终止身份不明进程 |

## 仍需关注的稳定性风险

以下为代码审查发现的具体风险，未声称它们已经在这两次实验中发生。此次功能修复集中于初始化映射的验收边界。

| 优先级 | 证据与触发条件 | 可能影响与建议 |
| --- | --- | --- |
| P1 | `start_server_quiet` 在解析到 PID 前就可能因 SSH 启动响应超时或丢失而抛错；主流程只有拿到 `server_pid` 才执行常规停止。 | 远端进程可能已经启动，当前防护会保留状态并报告回收不完整，下次可能因活动进程或端口占用被阻止。后续可按会话标记和 PID 文件恢复身份后停止，须测试 PID 复用和其他任务隔离。 |
| P2 | 每个任务的 `_end` 都调用 `export(self.root)`；导出重读全部历史原始记录，校验、汇总并写出 CSV。 | 历史记录越多，处理量和内存需求越高，任务间间隔可能延长。本地 53 项回放约 26 秒已说明这部分有可见开销。后续宜缓存已校验片段或增量导出；本次不重构数据处理。 |
| P2 | `_write_csv` 直接以写模式打开输出文件，没有清单保存所用的替换重试；原始日志采集中的本地文件替换也使用独立路径。 | Excel 等程序占用 CSV、磁盘写满等仍可能让导出失败并停止测试；运行期间避免打开正在生成的文件。后续可为可恢复的占用增加有界重试和临时文件提交，磁盘满仍应明确失败。 |
| P2 | `SSHRemote.run` 的主循环 deadline 在 `channel.exec_command` 返回后才建立；打开会话另有超时。 | 主循环超时并非整个 SSH 调用的统一总时限。启动命令确认异常时，墙钟耗时可能超过配置；需针对命令确认阶段另行验证，不能把当前 timeout 当作所有阶段的硬上限。 |
| P2 | `DEFAULT_VERIFY_SHA256=False`。 | 默认成功判据包含状态与字节数，不能等同于逐字节内容一致性验证。需要内容校验时可启用既有 `--verify-sha256`，并评估额外读取和哈希开销。 |
