# NetIns UDP 6.5 文件传输 Demo 编译说明

## 1. 适用范围

本文沿用 `路径正确的编译参考指南.md` 的编译方式和依赖路径，将版本、构建目录和目标换为当前文件传输版：

```text
AArch64/SIM8810 主板：netins_udp_mini_api_client
Linux x86_64 云服务器：netins_udp_mini_api_server
配套压测脚本：tests/副本改进版.py
```

两端使用当前工作目录的完整源码，包括 `demo/netins_udp_mini_api_server.c` 中尚未提交的 `--scheduler` 修改。不要只上传两个 Demo，也不要用旧提交中的服务端替代当前文件。

以下编译命令直接在 Linux Bash 中执行。先进入各自上传后的源码根目录；依赖路径沿用原指南，实际目录不同时只修改变量值。使用新的构建目录，不复用旧缓存，不覆盖当前 `CMakeLists.txt`。每项条件检查显示 `[通过]` 或 `[失败]` 及具体路径；失败时立即停止，修正后再继续。

## 2. 编译 AArch64 文件客户端

### 2.1 设置路径并检查

在客户端编译机的源码根目录执行：

```bash
set -e
FILE_SRC="$PWD"

FILE_ARM_SDK=/home/admin123/SIM8810_SDK_OCPU_LE3.0_1.1.0_251207
FILE_ARM_TC=/opt/crosstools/toolchain/gcc/usr/bin/aarch64-oe-linux
FILE_ARM_TLS="$FILE_SRC/../third_party/Tongsuo-8.3.0"
FILE_ARM_EVENT=/home/admin123/libevent_aarch64/libevent-2.1.12-stable
FILE_ARM_ZLOG=/home/admin123/zlog-1.2.18
FILE_CLIENT_BUILD="$FILE_SRC/build-file-client-aarch64-6.5"

export SIM8810_SDK_ROOT="$FILE_ARM_SDK"
export SIM8810_TOOLCHAIN_DIR="$FILE_ARM_TC"

cat VERSION
test "$(tr -d '\r\n' < "$FILE_SRC/VERSION")" = 6.5 && echo "[通过] 源码版本为6.5：$FILE_SRC/VERSION" || { echo "[失败] 源码版本不是6.5或无法读取：$FILE_SRC/VERSION"; exit 1; }
test -d "$FILE_ARM_SDK/sysroots_pvm" && echo "[通过] 目录存在：$FILE_ARM_SDK/sysroots_pvm" || { echo "[失败] 目录不存在：$FILE_ARM_SDK/sysroots_pvm"; exit 1; }
test -x "$FILE_ARM_TC/aarch64-oe-linux-gcc" && echo "[通过] 可执行：$FILE_ARM_TC/aarch64-oe-linux-gcc" || { echo "[失败] 文件不存在或不可执行：$FILE_ARM_TC/aarch64-oe-linux-gcc"; exit 1; }
test -x "$FILE_ARM_TC/aarch64-oe-linux-g++" && echo "[通过] 可执行：$FILE_ARM_TC/aarch64-oe-linux-g++" || { echo "[失败] 文件不存在或不可执行：$FILE_ARM_TC/aarch64-oe-linux-g++"; exit 1; }
test -f "$FILE_ARM_TLS/include/openssl/ssl.h" && echo "[通过] 文件存在：$FILE_ARM_TLS/include/openssl/ssl.h" || { echo "[失败] 文件不存在：$FILE_ARM_TLS/include/openssl/ssl.h"; exit 1; }
test -f "$FILE_ARM_TLS/libssl.a" && echo "[通过] 文件存在：$FILE_ARM_TLS/libssl.a" || { echo "[失败] 文件不存在：$FILE_ARM_TLS/libssl.a"; exit 1; }
test -f "$FILE_ARM_TLS/libcrypto.a" && echo "[通过] 文件存在：$FILE_ARM_TLS/libcrypto.a" || { echo "[失败] 文件不存在：$FILE_ARM_TLS/libcrypto.a"; exit 1; }
test -f "$FILE_ARM_EVENT/include/event2/event.h" && echo "[通过] 文件存在：$FILE_ARM_EVENT/include/event2/event.h" || { echo "[失败] 文件不存在：$FILE_ARM_EVENT/include/event2/event.h"; exit 1; }
test -f "$FILE_ARM_EVENT/.libs/libevent.a" && echo "[通过] 文件存在：$FILE_ARM_EVENT/.libs/libevent.a" || { echo "[失败] 文件不存在：$FILE_ARM_EVENT/.libs/libevent.a"; exit 1; }
test -f "$FILE_ARM_EVENT/.libs/libevent_pthreads.a" && echo "[通过] 文件存在：$FILE_ARM_EVENT/.libs/libevent_pthreads.a" || { echo "[失败] 文件不存在：$FILE_ARM_EVENT/.libs/libevent_pthreads.a"; exit 1; }
test -f "$FILE_ARM_ZLOG/src/zlog.h" && echo "[通过] 文件存在：$FILE_ARM_ZLOG/src/zlog.h" || { echo "[失败] 文件不存在：$FILE_ARM_ZLOG/src/zlog.h"; exit 1; }
test -f "$FILE_ARM_ZLOG/build_aarch64/lib/libzlog.a" && echo "[通过] 文件存在：$FILE_ARM_ZLOG/build_aarch64/lib/libzlog.a" || { echo "[失败] 文件不存在：$FILE_ARM_ZLOG/build_aarch64/lib/libzlog.a"; exit 1; }
```

版本应为 `6.5`。Tongsuo 路径与原指南相同，是源码目录旁的 `../third_party/Tongsuo-8.3.0`；如果源码位置变了，需相应调整这个变量。客户端全部静态依赖必须为 AArch64。

### 2.2 配置并编译

继续在同一个终端执行。构建目录如已存在，换一个新目录名后再执行，不删除旧产物。

```bash
test ! -e "$FILE_CLIENT_BUILD" && echo "[通过] 新构建目录：$FILE_CLIENT_BUILD" || { echo "[失败] 路径已存在，请更换构建目录：$FILE_CLIENT_BUILD"; exit 1; }

cmake -S "$FILE_SRC" -B "$FILE_CLIENT_BUILD" \
  -DCMAKE_TOOLCHAIN_FILE="$FILE_SRC/cmake/toolchains/sim8810-aarch64.cmake" \
  -DSIM8810_SDK_ROOT="$FILE_ARM_SDK" \
  -DSIM8810_TOOLCHAIN_DIR="$FILE_ARM_TC" \
  -DCMAKE_BUILD_TYPE=Release \
  -DXQC_ENABLE_MINI_API=ON \
  -DXQC_ENABLE_TESTING=OFF \
  -DSSL_TYPE=babassl \
  -DSSL_INC_PATH="$FILE_ARM_TLS/include" \
  -DSSL_LIB_PATH="$FILE_ARM_TLS/libssl.a;$FILE_ARM_TLS/libcrypto.a" \
  -DLIBEVENT_INCLUDE_DIR="$FILE_ARM_EVENT/include" \
  -DLIBEVENT_LIBRARY="$FILE_ARM_EVENT/.libs/libevent.a" \
  -DLIBEVENT_PTHREADS_LIBRARY="$FILE_ARM_EVENT/.libs/libevent_pthreads.a" \
  -DZLOG_INCLUDE_DIR="$FILE_ARM_ZLOG/src" \
  -DZLOG_STATIC_LIB="$FILE_ARM_ZLOG/build_aarch64/lib/libzlog.a"

cmake --build "$FILE_CLIENT_BUILD" \
  --target netins_udp_mini_api_client \
  --parallel "$(nproc)"
```

客户端产物：

```text
build-file-client-aarch64-6.5/mini/netins_udp_mini_api_client
build-file-client-aarch64-6.5/libxquic-static.a
```

检查架构并记录上传前的散列：

```bash
file "$FILE_CLIENT_BUILD/mini/netins_udp_mini_api_client"
"$FILE_ARM_TC/aarch64-oe-linux-readelf" -h \
  "$FILE_CLIENT_BUILD/mini/netins_udp_mini_api_client" | grep Machine
sha256sum "$FILE_CLIENT_BUILD/mini/netins_udp_mini_api_client"
```

结果必须包含 `ARM aarch64` 或 `AArch64`。上传到目标主板运行，不在 x86_64 编译机上运行。

## 3. 编译 Linux x86_64 文件服务端

### 3.1 设置路径并检查

在服务端编译机的源码根目录执行，使用原指南的 `/data/quic/` 依赖路径：

```bash
set -e
FILE_SRC="$PWD"

FILE_LINUX_TLS=/data/quic/zz_xquic_3090/third_party/Tongsuo-8.3.0
FILE_LINUX_EVENT=/data/quic/libevent-2.1.12-stable
FILE_LINUX_ZLOG=/data/quic/zlog-1.2.18
FILE_LINUX_SSL_LIB="$FILE_LINUX_TLS/libssl.a"
FILE_LINUX_CRYPTO_LIB="$FILE_LINUX_TLS/libcrypto.a"
FILE_SERVER_BUILD="$FILE_SRC/build-file-server-linux-6.5"



test "$(uname -m)" = x86_64 && echo "[通过] 编译机架构为x86_64" || { echo "[失败] 编译机架构应为x86_64，实际为：$(uname -m)"; exit 1; }
test -x /usr/bin/gcc && echo "[通过] 可执行：/usr/bin/gcc" || { echo "[失败] 文件不存在或不可执行：/usr/bin/gcc"; exit 1; }
test -x /usr/bin/g++ && echo "[通过] 可执行：/usr/bin/g++" || { echo "[失败] 文件不存在或不可执行：/usr/bin/g++"; exit 1; }
test -f "$FILE_LINUX_TLS/include/openssl/ssl.h" && echo "[通过] 文件存在：$FILE_LINUX_TLS/include/openssl/ssl.h" || { echo "[失败] 文件不存在：$FILE_LINUX_TLS/include/openssl/ssl.h"; exit 1; }
test -f "$FILE_LINUX_SSL_LIB" && echo "[通过] 文件存在：$FILE_LINUX_SSL_LIB" || { echo "[失败] 文件不存在：$FILE_LINUX_SSL_LIB"; exit 1; }
test -f "$FILE_LINUX_CRYPTO_LIB" && echo "[通过] 文件存在：$FILE_LINUX_CRYPTO_LIB" || { echo "[失败] 文件不存在：$FILE_LINUX_CRYPTO_LIB"; exit 1; }
test -f "$FILE_LINUX_EVENT/include/event2/event.h" && echo "[通过] 文件存在：$FILE_LINUX_EVENT/include/event2/event.h" || { echo "[失败] 文件不存在：$FILE_LINUX_EVENT/include/event2/event.h"; exit 1; }
test -f "$FILE_LINUX_EVENT/.libs/libevent.a" && echo "[通过] 文件存在：$FILE_LINUX_EVENT/.libs/libevent.a" || { echo "[失败] 文件不存在：$FILE_LINUX_EVENT/.libs/libevent.a"; exit 1; }
test -f "$FILE_LINUX_EVENT/.libs/libevent_pthreads.a" && echo "[通过] 文件存在：$FILE_LINUX_EVENT/.libs/libevent_pthreads.a" || { echo "[失败] 文件不存在：$FILE_LINUX_EVENT/.libs/libevent_pthreads.a"; exit 1; }
test -f "$FILE_LINUX_ZLOG/src/zlog.h" && echo "[通过] 文件存在：$FILE_LINUX_ZLOG/src/zlog.h" || { echo "[失败] 文件不存在：$FILE_LINUX_ZLOG/src/zlog.h"; exit 1; }
test -f "$FILE_LINUX_ZLOG/build_x86_64/lib/libzlog.a" && echo "[通过] 文件存在：$FILE_LINUX_ZLOG/build_x86_64/lib/libzlog.a" || { echo "[失败] 文件不存在：$FILE_LINUX_ZLOG/build_x86_64/lib/libzlog.a"; exit 1; }


grep -F 'scheduler-switch-v1' demo/netins_udp_mini_api_server.c && echo "[通过] 服务端算法切换标记：$FILE_SRC/demo/netins_udp_mini_api_server.c" || { echo "[失败] 缺少算法切换标记或无法读取：$FILE_SRC/demo/netins_udp_mini_api_server.c"; exit 1; }
```

版本应为 `6.5`，最后一条应找到当前服务端的构建标记。服务器全部静态依赖必须为 x86_64。

如果 TLS 库找不到，按原指南查实际位置：

```bash
find "$FILE_LINUX_TLS" -maxdepth 2 \
  \( -name libssl.a -o -name libcrypto.a \) -print
```

只有实际位于 `lib/` 时，才将前面的两个库变量改为 `$FILE_LINUX_TLS/lib/libssl.a`、`$FILE_LINUX_TLS/lib/libcrypto.a`，然后重新检查。

### 3.2 配置并编译

继续在同一个终端执行。显式指定本机 GCC/G++，避免当前根 CMake 使用默认 AArch64 交叉工具链。

```bash
test ! -e "$FILE_SERVER_BUILD" && echo "[通过] 新构建目录：$FILE_SERVER_BUILD" || { echo "[失败] 路径已存在，请更换构建目录：$FILE_SERVER_BUILD"; exit 1; }

cmake -S "$FILE_SRC" -B "$FILE_SERVER_BUILD" \
  -DCMAKE_C_COMPILER=/usr/bin/gcc \
  -DCMAKE_CXX_COMPILER=/usr/bin/g++ \
  -DCMAKE_BUILD_TYPE=Release \
  -DXQC_ENABLE_MINI_API=ON \
  -DXQC_ENABLE_TESTING=OFF \
  -DSSL_TYPE=babassl \
  -DSSL_INC_PATH="$FILE_LINUX_TLS/include" \
  -DSSL_LIB_PATH="$FILE_LINUX_SSL_LIB;$FILE_LINUX_CRYPTO_LIB" \
  -DLIBEVENT_INCLUDE_DIR="$FILE_LINUX_EVENT/include" \
  -DLIBEVENT_LIBRARY="$FILE_LINUX_EVENT/.libs/libevent.a" \
  -DLIBEVENT_PTHREADS_LIBRARY="$FILE_LINUX_EVENT/.libs/libevent_pthreads.a" \
  -DZLOG_INCLUDE_DIR="$FILE_LINUX_ZLOG/src" \
  -DZLOG_STATIC_LIB="$FILE_LINUX_ZLOG/build_x86_64/lib/libzlog.a"

cmake --build "$FILE_SERVER_BUILD" \
  --target netins_udp_mini_api_server \
  --parallel "$(nproc)"
```

服务端产物：

```text
build-file-server-linux-6.5/mini/netins_udp_mini_api_server
build-file-server-linux-6.5/libxquic-static.a
```

检查架构、动态依赖和算法参数：

```bash
file "$FILE_SERVER_BUILD/mini/netins_udp_mini_api_server"
readelf -h "$FILE_SERVER_BUILD/mini/netins_udp_mini_api_server" | grep Machine
ldd "$FILE_SERVER_BUILD/mini/netins_udp_mini_api_server"
sha256sum "$FILE_SERVER_BUILD/mini/netins_udp_mini_api_server"
"$FILE_SERVER_BUILD/mini/netins_udp_mini_api_server" --version
"$FILE_SERVER_BUILD/mini/netins_udp_mini_api_server" --help 2>&1 | grep -- --scheduler
```

`Machine` 应为 `Advanced Micro Devices X86-64`，`ldd` 不应出现 `not found`。版本输出应含 `api_release=6.5` 和 `scheduler-switch-v1`，帮助输出应含 `--scheduler`。当前 Demo 的 `--help` 自身退出码为 1，打印出参数说明属于正常行为。

## 4. 部署到副本改进版使用的位置

备份原有程序后，通过已有文件传输方式上传本次产物和两个监控脚本：

| 机器 | 文件 | 部署路径 |
|---|---|---|
| 主板 | AArch64 `netins_udp_mini_api_client` | `/oemdata/gx/xquic_file/netins_udp_mini_api_client` |
| 主板 | `tests/monitor_board_resource.sh` | `/oemdata/monitor_board_resource.sh` |
| 云服务器 | x86_64 `netins_udp_mini_api_server` | `/root/test_xquic_server/netins_udp_mini_api_server` |
| 云服务器 | `tests/monitor_server_memory.sh` | `/root/test_xquic_server/monitor_server_memory.sh` |

主板执行：

```bash
cd /oemdata/gx/xquic_file
chmod +x netins_udp_mini_api_client /oemdata/monitor_board_resource.sh
./netins_udp_mini_api_client --version
ldd ./netins_udp_mini_api_client
sha256sum ./netins_udp_mini_api_client
test -s download/kkk.txt && echo "[通过] 文件非空：$PWD/download/kkk.txt" || { echo "[失败] 文件不存在或为空：$PWD/download/kkk.txt"; exit 1; }
```

云服务器执行：

```bash
cd /root/test_xquic_server
chmod +x netins_udp_mini_api_server monitor_server_memory.sh
./netins_udp_mini_api_server --version
./netins_udp_mini_api_server --help 2>&1 | grep -- --scheduler
sha256sum ./netins_udp_mini_api_server
test -s server.crt && echo "[通过] 文件非空：$PWD/server.crt" || { echo "[失败] 文件不存在或为空：$PWD/server.crt"; exit 1; }
test -s server.key && echo "[通过] 文件非空：$PWD/server.key" || { echo "[失败] 文件不存在或为空：$PWD/server.key"; exit 1; }
test -s upload/1 && echo "[通过] 文件非空：$PWD/upload/1" || { echo "[失败] 文件不存在或为空：$PWD/upload/1"; exit 1; }
test -w upload && echo "[通过] 目录可写：$PWD/upload" || { echo "[失败] 目录不存在或不可写：$PWD/upload"; exit 1; }
ss -lunp | grep ':18446 ' || true
```

部署后的二进制散列应与构建机记录一致；主板若没有 `ldd`，先确认 `--version` 可以正常启动。两端需要 Bash 和原监控脚本使用的系统命令；监控脚本按 LF 换行上传。

脚本使用服务器 UDP `18446`。`upload/1` 是服务器的 GET 源文件，主板 `download/kkk.txt` 是 POST 源文件，两者都要非空。服务器 `upload/` 需要可写。当前脚本明确检查并传入外部 `server.crt/server.key`，不能省略这两个文件。

## 5. 运行原有文件压测脚本

在 Windows 控制机的仓库根目录运行原有脚本：

```powershell
python ".\tests\副本改进版.py" --iterations 1 --verify-sha256
```

这里的 Python 仅用于启动已有压测入口，不需要新增 Python 校验程序。当前默认测试 `adaptive`、`minrtt`，每种算法执行三个链路的 GET/POST，共 12 项。脚本自行启动服务端，运行前不要手动占用 UDP 18446。

真实运行退出码为 0、`case_results.csv` 全部为 `SUCCESS`，并检查日志中的服务端实际算法及两端资源监控状态后，才确认本次程序可用于压测。`--verify-sha256` 开启文件内容完整性校验。

本指南已按当前源码核对构建目标、参数和路径，并检查命令语法；远端依赖路径是否存在、实际编译和目标机运行仍以两端执行结果为准。
