# 实验代码 V1.0 可执行文件编译指南

## 1. 适用范围

本文用于编译实验采集版本的两个 Mini API 文件传输程序：

```text
AArch64/SIM8810 主板：netins_udp_mini_api_client
Linux x86_64 云服务器：netins_udp_mini_api_server
```

本文沿用已验证环境中的 SDK、工具链、Tongsuo、Libevent 和 zlog 路径，只更换源码版本、构建目标和构建目录。实验版不需要新增 CMake 选项，继续使用 `-DXQC_ENABLE_MINI_API=ON`。

为避免与旧文件传输版和数据流版混淆，固定使用以下全新构建目录：

```text
build-experiment-telemetry-v1_0-client-aarch64
build-experiment-telemetry-v1_0-server-x86_64
```

不要复用这些旧目录：

```text
build/
build-mini-api-*
build-stream-*
```

## 2. 准备完整实验版源码

客户端和服务端编译机都必须使用提交 `6a000192` 或其后的完整 `codex/experiment-telemetry` 分支源码。不能只复制两个 Demo 或 `tests` 目录，因为传输指标还依赖公共头文件、Mini backend、NetIns API 和 XQUIC transport 修改。

建议在两台编译机上为实验版准备独立源码目录：

```text
/实际路径/xquic-experiment-telemetry-v1.0/
```

通过现有文件传输方式上传完整源码时，不要上传：

```text
.git/
build*/
stage/
delivery/
.venv*/
tests/log/
*.o
*.a
*.so
```

上传后进入源码根目录并检查：

```bash
cd /实际路径/xquic-experiment-telemetry-v1.0

cat VERSION
grep 'NETINS_UDP_API_RELEASE_VERSION' include/xquic/netins_udp.h
grep 'NETINS_UDP_EXPERIMENT_VERSION' include/xquic/netins_udp.h
test -f demo/netins_udp_telemetry_json.c
grep 'netins_udp_telemetry_json.c' mini/CMakeLists.txt
grep 'add_executable(netins_udp_mini_api_client' mini/CMakeLists.txt
grep 'add_executable(netins_udp_mini_api_server' mini/CMakeLists.txt
```

关键输出应包含：

```text
6.5
#define NETINS_UDP_API_RELEASE_VERSION "6.5"
#define NETINS_UDP_EXPERIMENT_VERSION "实验代码V1.0"
```

如果实验版本宏、JSONL 源文件或任一 Mini API 构建目标缺失，说明源码没有上传完整，不要继续编译。

## 3. 编译 AArch64/SIM8810 实验客户端

以下依赖路径直接沿用已验证的客户端编译环境：

```bash
cd /实际路径/xquic-experiment-telemetry-v1.0
EXPERIMENT_SRC="$PWD"

EXPERIMENT_ARM_SDK=/home/admin123/SIM8810_SDK_OCPU_LE3.0_1.1.0_251207
EXPERIMENT_ARM_TC=/opt/crosstools/toolchain/gcc/usr/bin/aarch64-oe-linux
EXPERIMENT_ARM_TLS="$EXPERIMENT_SRC/../third_party/Tongsuo-8.3.0"
EXPERIMENT_ARM_EVENT=/home/admin123/libevent_aarch64/libevent-2.1.12-stable
EXPERIMENT_ARM_ZLOG=/home/admin123/zlog-1.2.18
EXPERIMENT_CLIENT_BUILD="$EXPERIMENT_SRC/build-experiment-telemetry-v1_0-client-aarch64"

export SIM8810_SDK_ROOT="$EXPERIMENT_ARM_SDK"
export SIM8810_TOOLCHAIN_DIR="$EXPERIMENT_ARM_TC"
```

先检查全部路径，任一检查失败都应停止：

```bash
test -d "$EXPERIMENT_ARM_SDK/sysroots_pvm" && echo "[OK] SIM8810 sysroot" || exit 1
test -x "$EXPERIMENT_ARM_TC/aarch64-oe-linux-gcc" && echo "[OK] AArch64 gcc" || exit 1
test -x "$EXPERIMENT_ARM_TC/aarch64-oe-linux-g++" && echo "[OK] AArch64 g++" || exit 1
test -f "$EXPERIMENT_ARM_TLS/include/openssl/ssl.h" && echo "[OK] ssl.h" || exit 1
test -f "$EXPERIMENT_ARM_TLS/libssl.a" && echo "[OK] AArch64 libssl.a" || exit 1
test -f "$EXPERIMENT_ARM_TLS/libcrypto.a" && echo "[OK] AArch64 libcrypto.a" || exit 1
test -f "$EXPERIMENT_ARM_EVENT/include/event2/event.h" && echo "[OK] event.h" || exit 1
test -f "$EXPERIMENT_ARM_EVENT/.libs/libevent.a" && echo "[OK] AArch64 libevent.a" || exit 1
test -f "$EXPERIMENT_ARM_EVENT/.libs/libevent_pthreads.a" && echo "[OK] AArch64 libevent_pthreads.a" || exit 1
test -f "$EXPERIMENT_ARM_ZLOG/src/zlog.h" && echo "[OK] zlog.h" || exit 1
test -f "$EXPERIMENT_ARM_ZLOG/build_aarch64/lib/libzlog.a" && echo "[OK] AArch64 libzlog.a" || exit 1
```

创建全新的实验客户端构建目录并编译：

```bash
rm -rf -- "$EXPERIMENT_CLIENT_BUILD"

cmake -S "$EXPERIMENT_SRC" -B "$EXPERIMENT_CLIENT_BUILD" \
  -DCMAKE_TOOLCHAIN_FILE="$EXPERIMENT_SRC/cmake/toolchains/sim8810-aarch64.cmake" \
  -DSIM8810_SDK_ROOT="$EXPERIMENT_ARM_SDK" \
  -DSIM8810_TOOLCHAIN_DIR="$EXPERIMENT_ARM_TC" \
  -DCMAKE_BUILD_TYPE=Release \
  -DXQC_ENABLE_MINI_API=ON \
  -DXQC_ENABLE_TESTING=OFF \
  -DSSL_TYPE=babassl \
  -DSSL_INC_PATH="$EXPERIMENT_ARM_TLS/include" \
  -DSSL_LIB_PATH="$EXPERIMENT_ARM_TLS/libssl.a;$EXPERIMENT_ARM_TLS/libcrypto.a" \
  -DLIBEVENT_INCLUDE_DIR="$EXPERIMENT_ARM_EVENT/include" \
  -DLIBEVENT_LIBRARY="$EXPERIMENT_ARM_EVENT/.libs/libevent.a" \
  -DLIBEVENT_PTHREADS_LIBRARY="$EXPERIMENT_ARM_EVENT/.libs/libevent_pthreads.a" \
  -DZLOG_INCLUDE_DIR="$EXPERIMENT_ARM_ZLOG/src" \
  -DZLOG_STATIC_LIB="$EXPERIMENT_ARM_ZLOG/build_aarch64/lib/libzlog.a"

cmake --build "$EXPERIMENT_CLIENT_BUILD" \
  --target netins_udp_mini_api_client \
  --parallel "$(nproc)"
```

生成文件：

```text
build-experiment-telemetry-v1_0-client-aarch64/mini/netins_udp_mini_api_client
build-experiment-telemetry-v1_0-client-aarch64/libxquic-static.a
```

检查架构和实验版本字符串：

```bash
file "$EXPERIMENT_CLIENT_BUILD/mini/netins_udp_mini_api_client"
"$EXPERIMENT_ARM_TC/aarch64-oe-linux-readelf" -h \
  "$EXPERIMENT_CLIENT_BUILD/mini/netins_udp_mini_api_client" | grep Machine
strings "$EXPERIMENT_CLIENT_BUILD/mini/netins_udp_mini_api_client" | grep 'V1.0'
sha256sum "$EXPERIMENT_CLIENT_BUILD/mini/netins_udp_mini_api_client"
```

架构必须为 `ARM aarch64` 或 `AArch64`。交叉编译产物不能直接在 x86_64 编译机运行。

## 4. 编译 Linux x86_64 实验服务端

以下依赖路径直接沿用已验证的服务端编译环境：

```bash
cd /实际路径/xquic-experiment-telemetry-v1.0
EXPERIMENT_SRC="$PWD"

EXPERIMENT_LINUX_TLS=/data/quic/zz_xquic_3090/third_party/Tongsuo-8.3.0
EXPERIMENT_LINUX_EVENT=/data/quic/libevent-2.1.12-stable
EXPERIMENT_LINUX_ZLOG=/data/quic/zlog-1.2.18
EXPERIMENT_LINUX_SSL_LIB="$EXPERIMENT_LINUX_TLS/libssl.a"
EXPERIMENT_LINUX_CRYPTO_LIB="$EXPERIMENT_LINUX_TLS/libcrypto.a"
EXPERIMENT_SERVER_BUILD="$EXPERIMENT_SRC/build-experiment-telemetry-v1_0-server-x86_64"
```

```bash
test "$(uname -m)" = x86_64 && echo "[OK] x86_64" || exit 1

test -f "$EXPERIMENT_LINUX_TLS/include/openssl/ssl.h" && echo "[OK] ssl.h" || exit 1
test -f "$EXPERIMENT_LINUX_SSL_LIB" && echo "[OK] x86_64 libssl.a" || exit 1
test -f "$EXPERIMENT_LINUX_CRYPTO_LIB" && echo "[OK] x86_64 libcrypto.a" || exit 1
test -f "$EXPERIMENT_LINUX_EVENT/include/event2/event.h" && echo "[OK] event.h" || exit 1
test -f "$EXPERIMENT_LINUX_EVENT/.libs/libevent.a" && echo "[OK] x86_64 libevent.a" || exit 1
test -f "$EXPERIMENT_LINUX_EVENT/.libs/libevent_pthreads.a" && echo "[OK] x86_64 libevent_pthreads.a" || exit 1
test -f "$EXPERIMENT_LINUX_ZLOG/src/zlog.h" && echo "[OK] zlog.h" || exit 1
test -f "$EXPERIMENT_LINUX_ZLOG/build_x86_64/lib/libzlog.a" && echo "[OK] x86_64 libzlog.a" || exit 1
```

创建全新的实验服务端构建目录并编译：

```bash
rm -rf -- "$EXPERIMENT_SERVER_BUILD"

cmake -S "$EXPERIMENT_SRC" -B "$EXPERIMENT_SERVER_BUILD" \
  -DCMAKE_C_COMPILER=/usr/bin/gcc \
  -DCMAKE_CXX_COMPILER=/usr/bin/g++ \
  -DCMAKE_BUILD_TYPE=Release \
  -DXQC_ENABLE_MINI_API=ON \
  -DXQC_ENABLE_TESTING=OFF \
  -DSSL_TYPE=babassl \
  -DSSL_INC_PATH="$EXPERIMENT_LINUX_TLS/include" \
  -DSSL_LIB_PATH="$EXPERIMENT_LINUX_SSL_LIB;$EXPERIMENT_LINUX_CRYPTO_LIB" \
  -DLIBEVENT_INCLUDE_DIR="$EXPERIMENT_LINUX_EVENT/include" \
  -DLIBEVENT_LIBRARY="$EXPERIMENT_LINUX_EVENT/.libs/libevent.a" \
  -DLIBEVENT_PTHREADS_LIBRARY="$EXPERIMENT_LINUX_EVENT/.libs/libevent_pthreads.a" \
  -DZLOG_INCLUDE_DIR="$EXPERIMENT_LINUX_ZLOG/src" \
  -DZLOG_STATIC_LIB="$EXPERIMENT_LINUX_ZLOG/build_x86_64/lib/libzlog.a"

cmake --build "$EXPERIMENT_SERVER_BUILD" \
  --target netins_udp_mini_api_server \
  --parallel "$(nproc)"
```

生成文件：

```text
build-experiment-telemetry-v1_0-server-x86_64/mini/netins_udp_mini_api_server
build-experiment-telemetry-v1_0-server-x86_64/libxquic-static.a
```

检查架构、运行时依赖、实验版本和摘要：

```bash
file "$EXPERIMENT_SERVER_BUILD/mini/netins_udp_mini_api_server"
readelf -h "$EXPERIMENT_SERVER_BUILD/mini/netins_udp_mini_api_server" | grep Machine
ldd "$EXPERIMENT_SERVER_BUILD/mini/netins_udp_mini_api_server"
"$EXPERIMENT_SERVER_BUILD/mini/netins_udp_mini_api_server" --version
sha256sum "$EXPERIMENT_SERVER_BUILD/mini/netins_udp_mini_api_server"
```

`Machine` 必须为 `Advanced Micro Devices X86-64`，`ldd` 不应出现 `not found`，版本输出必须包含：

```text
[experiment] 实验代码V1.0 role=server api_release=6.5
```

## 5. 独立命名部署

CMake 目标名称保持不变，以免改动原构建接口。为避免远端目录中的旧程序混淆，建议在上传时重命名：

```text
主板：/oemdata/gx/xquic_file/netins_udp_mini_api_client_experiment_v1_0
云端：/root/test_xquic_server/netins_udp_mini_api_server_experiment_v1_0
```

上传后执行：

```bash
chmod +x ./netins_udp_mini_api_client_experiment_v1_0
./netins_udp_mini_api_client_experiment_v1_0 --version
```

```bash
chmod +x ./netins_udp_mini_api_server_experiment_v1_0
./netins_udp_mini_api_server_experiment_v1_0 --version
```

两端都必须显示“实验代码V1.0”。主板如提供 `ldd`，再执行：

```bash
ldd ./netins_udp_mini_api_client_experiment_v1_0
```

输出不得包含 `not found`。

压测脚本使用独立文件名时，在控制电脑的脚本目录执行：

```powershell
python .\压测脚本.py `
  --client-executable ./netins_udp_mini_api_client_experiment_v1_0 `
  --server-executable ./netins_udp_mini_api_server_experiment_v1_0 `
  --iterations 1 `
  --direction both
```

如果仍使用默认文件名部署，则不传这两个覆盖参数。
