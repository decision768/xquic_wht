# 实验测试脚本改造方案 v1.0

## 1. 目标、口径与当前状态

在保留现有文件压测顺序、算法、重试、超时、冷却和完整性校验的基础上，增加发送端结构化周期采样，并在运行压测脚本的电脑上汇总为 Excel。

固定采集：

- 两条路径的 CWND、SRTT、CWND/RTT。
- 两条路径的在途包数 InP、InP/RTT。
- 连接共享 SWND，以及分别使用两条路径 SRTT 计算的 SWND/RTT。
- 5G1、5G2的LTE/NR RSRP、RSRQ、SNR原始值和可用RSSI。
- 两条路径和两张网卡的周期速率。
- 原有整次传输速度和聚合率。

已确定口径：

- `InP` 是当前仍被拥塞控制计为在途的 ACK-eliciting QUIC 包数量；已确认或已判丢的包退出统计，重传包按新包重新计数。
- `SWND = min(连接剩余流控额度, 活动双向文件流剩余额度之和)`。
- SWND属于连接共享状态，不虚构两条独立窗口；同一个SWND分别除以两条路径的SRTT。
- SNR直接保存 `test_api` 原始值，不推测除以10，也不标成未经确认的dB。
- 默认C侧采样周期250 ms、网卡500 ms、信号1 s、Excel联合时间轴1 s，均允许命令行覆盖。
- GET采用云服务器发送端数据，POST采用主板客户端发送端数据。
- 所有比值由Python使用C侧原始值计算；RTT为零时留空。
- 采集故障不改变文件传输结果，缺失字段留空并记录原因。
- 主板和服务器都需要使用本次源码重新编译的程序。

截至2026-09-08，源码改造和本机静态审查已完成；目标板、云服务器编译部署及正式联调尚未执行。旧文档中“只改Python、不计算SWND、逐路径参数不可获取”等结论已经失效，以本文为准。

## 2. 最小化实现方案

### 2.1 XQUIC内部传输指标

只在现有状态维护和读取链路上增加必要字段，不改拥塞算法与调度器。

- 在 `xqc_send_ctl_t` 增加逐路径 `ctl_packets_in_flight`。
- 在现有 `xqc_send_ctl_increase_inflight()` 中，与 `ctl_bytes_in_flight` 同条件加一。
- 在现有 `xqc_send_ctl_decrease_inflight()` 中，与字节数同条件减一，并做下限保护。
- ACK-only、未发送排队包不计入；判丢原包退出，重传或重注入包在实际发送路径重新进入。
- 增加按输出指针填充的内部遥测读取函数，不修改现有按值返回的 `xqc_conn_stats_t`，避免破坏共享库ABI。
- 一次调用读取整个连接和全部路径，返回：
  - 路径ID、状态和SRTT。
  - 拥塞控制算法原始CWND。
  - 经 `so_sndbuf` 上限处理后的有效CWND。
  - 在途包数和在途字节数。
  - 路径累计应用数据发送字节。
  - 连接剩余流控额度。
  - 活动双向数据流剩余额度之和。
  - 有效SWND。

连接和流额度使用饱和减法：

```text
connection_credit = max(0, fc_max_data_can_send - fc_data_sent)

stream_credit = max(
    0,
    fc_max_stream_data_can_send - stream_send_offset
)

effective_swnd = min(
    connection_credit,
    sum(active_bidirectional_file_stream_credit)
)
```

文件API模式下只统计仍可由本端发送的活动双向请求流，排除HTTP/3控制流、已关闭流和纯接收流。

### 2.2 NetIns/Mini结构化遥测接口

采用新增接口，不改现有文件传输函数的行为或参数语义。

在公开NetIns接口中增加：

```text
NETINS_UDP_OPT_TELEMETRY
netins_udp_telemetry_config_t
netins_udp_telemetry_sample_t
netins_udp_path_telemetry_t
netins_udp_telemetry_cb
```

配置包含：

- 是否启用。
- 采样周期毫秒数。
- 最大长度受限的 `attempt_id`。
- 遥测回调和用户数据。

样本包含：

- 结构版本。
- `attempt_id`、连接标识、发送端角色和GET/POST方向。
- `start`、`periodic`、`end`样本类型。
- 采样序号、计划单调时刻、实际单调时刻、实时时钟和迟到量。
- 跳过的周期数量。
- 共享流控字段。
- 固定容量的路径数组和各路径原始指标。

兼容规则：

- 接口为增量新增，不改变已有 `netins_udp_transfer()`、`netins_udp_serve()` 和结束快照调用方式。
- 不扩大或改变现有 `xqc_conn_stats_t` 的返回布局。
- 新结构继续采用 `struct_size + api_version` 校验。
- 现有结束快照中的 `cwnd_bytes`、`bytes_inflight` 可同步填入真实值，但周期数据以新遥测样本为准。
- 未配置遥测时不创建定时器、不写文件，执行路径与原程序一致。

### 2.3 固定周期调度

客户端和服务端都在各自Mini/libevent线程中采样，不从外部线程并发遍历XQUIC状态。

- POST：客户端在首个文件请求体提交时进入载荷阶段，由客户端事件循环采样。
- GET：服务器解析首个有效GET请求并开始发送响应体时进入载荷阶段，由服务端事件循环采样。
- 载荷开始立即输出 `start` 样本。
- 周期采用绝对期限 `next_deadline += interval`。
- 延迟时只输出一次当前样本并记录 `lateness_us`、`missed_intervals`，不突发补写历史样本。
- 最后一个文件分片完成或连接提前失败时输出 `end` 样本并释放事件。
- 一次回调同时读取全部路径，保证两路数据时间一致。
- 遥测回调或文件写入失败时关闭该连接的后续遥测并记录错误，不令文件传输失败。
- 250 ms采样只执行固定字段读取和最多8条路径遍历，不打印DEBUG洪泛日志。

### 2.4 测试编号与路径归属

Python继续使用现有唯一 `run_tag` 作为 `attempt_id`：

```text
session + round + mode + direction + retry
```

客户端新增参数：

```text
--attempt-id
--telemetry-output
--telemetry-interval-ms
```

服务器新增参数：

```text
--telemetry-output
--telemetry-interval-ms
```

客户端在每个文件分片请求中附加：

```text
x-mini-bench-id: <attempt_id>
```

处理规则：

- 仅接受ASCII字母、数字、点、下划线和短横线，并限制长度。
- 同一连接后续分片必须使用相同编号。
- 缺失或非法编号只使服务器样本标记为无编号，不中止文件传输。
- 服务器启动一次，所有连接写入一个会话级JSONL；每条记录自身携带 `attempt_id`。
- Python下载后按 `attempt_id` 拆分到本机每次尝试目录。

客户端样本包含现有：

```text
path_id → interface_name → local_address
```

映射，其中：

```text
rmnet_data0 → 5G1
usb0        → 5G2
```

GET服务器样本通过同一连接的 `attempt_id + path_id` 与客户端路径映射关联，不固定假设路径0属于5G1。路径新增、关闭或重绑定时重新记录映射。

### 2.5 C侧JSONL输出

新增一个客户端、服务端共用的小型JSONL写入模块，只负责序列化和文件生命周期，不承担采样计算。

每条记录一行，至少包含：

```json
{
  "schema_version": 1,
  "attempt_id": "api_...",
  "role": "server",
  "direction": "get",
  "sample_kind": "periodic",
  "sample_seq": 12,
  "scheduled_mono_us": 123000000,
  "actual_mono_us": 123004000,
  "realtime_us": 1780000000000000,
  "lateness_us": 4000,
  "connection_credit_bytes": 8388608,
  "active_stream_credit_bytes": 16777216,
  "effective_swnd_bytes": 8388608,
  "paths": [
    {
      "path_id": 0,
      "path_state": 2,
      "interface_name": "rmnet_data0",
      "cwnd_bytes": 524288,
      "effective_cwnd_bytes": 524288,
      "inflight_packets": 43,
      "inflight_bytes": 58050,
      "srtt_us": 32000,
      "sent_bytes": 104857600
    }
  ]
}
```

写入规则：

- JSON字段名称和单位固定，数值不预先格式化为字符串。
- C侧不计算CWND/RTT、InP/RTT和SWND/RTT。
- 客户端每次尝试写一个临时JSONL。
- 服务端每次会话写一个JSONL。
- 输出路径由Python传入并做shell安全引用。
- 仅遥测文件失败时不影响stdout中的原传输结果。
- 正常退出刷新并关闭；异常中断允许保留最后一条不完整行，由Python报告并跳过。

### 2.6 Python总控与数据汇总

以 `tests/压测脚本.py` 为唯一入口，保持原六项顺序：

```text
GET：5G1 → 聚合 → 5G2
POST：5G1 → 聚合 → 5G2
```

每次尝试的工作流：

1. 创建 `attempt_id` 和远端临时文件名。
2. 记录主板、服务器时钟探测结果。
3. 启动或确认5G1、5G2信号和网卡采集器。
4. 将 `attempt_id`、采样周期和输出路径传给客户端。
5. 运行原文件传输命令。
6. 无论成功、失败或超时，都尝试停止本次遥测并下载部分JSONL。
7. 校验原文件大小、摘要、退出码和原吞吐量结果。
8. 解析C侧样本，关联路径和信号。
9. 删除本次明确拥有且已成功下载的远端临时文件。
10. 进入原重试或冷却流程。

服务器在整次压测开始时启动，增加会话级遥测输出路径；其stdout/stderr处理保持原状。最终或可处理的中断中下载服务端JSONL。下载失败时记录远端保留路径，不扩大清理范围。

`benchmark_telemetry.py`在现有功能上增加：

- C侧JSONL严格解析和结构版本校验。
- 主板、服务器单调时钟到控制电脑单调时钟的映射。
- `attempt_id + path_id`归属。
- GET只采用服务器发送端周期指标；POST只采用客户端发送端周期指标。
- 250 ms原始传输样本按1秒测试时间窗汇总。
- 原始JSONL持续保留，可离线重新生成Excel。

一秒汇总规则：

- 时间窗以发送端载荷开始时刻为零点。
- CWND、SRTT、InP、SWND及三个比值使用该窗内有效样本的算术平均。
- 路径周期速度按窗首尾累计发送字节及实际时间差计算。
- 信号使用查询中点落在该窗内的有效样本；没有样本时留空，不沿用上一秒。
- 网卡速度使用与时间窗重叠区间的按时长加权平均。
- 每个字段同时保存有效样本数；没有有效RTT时三个比值留空。
- 跨测试边界、初始化、冷却和收尾样本不进入测试均值。

计算公式：

```text
CWND/RTT（Mbps）
= 8 × cwnd_bytes / srtt_us

InP/RTT（packets/s）
= 1,000,000 × inflight_packets / srtt_us

SWND/RTT（Mbps）
= 8 × effective_swnd_bytes / srtt_us

路径周期速度（Mbps）
= 8 × Δsent_bytes / Δtime_us

聚合率（%）
= Agg_mbps / (5G1_mbps + 5G2_mbps) × 100
```

SWND在两条路径行中共享，禁止相加。路径累计发送字节可能包含重传或重注入产生的再次发送，因此周期路径速度标记为发送端路径速率；原有整次文件吞吐量仍是主要传输速度。

### 2.7 双模块信号

沿用已经实现的独立采集通道：

- 5G1：主板SSH独立PTY运行 `/oemapp/usr/bin/test_api`。
- 5G2：控制电脑COM11，115200、8N1、无流控。
- 每个会话执行一次 `15 → 20`，之后每1秒发送一次 `25`。
- 同一模块不重叠查询；上次未结束时跳过本周期。
- 必须等完整数值和下一次菜单边界，不能见到 `OK` 就结束。
- 保存查询开始、结束、中点、原始文本、有效标志和解析状态。
- LTE、NR字段分别保存；无NR RSSI时留空。
- 字段命名为 `snr_raw`，Excel标题明确为“test_api原始值”。

信号查询失败、串口被占用或SSH通道断开时，停止对应采集器，其他采集和文件传输继续。

Excel固定为三个工作表：

## 4. 实施顺序与失败处理

1. 更新文档为v1.0，保留已确认的拓扑、串口和原测试规则，删除旧范围冲突。
2. 实现在途包计数和内部遥测读取，先保证不改变现有发送判断。
3. 增加NetIns遥测配置、Mini定时器和载荷开始/结束事件。
4. 增加 `attempt_id` 请求头和服务器关联。
5. 增加共用JSONL写入器及客户端、服务端命令行参数。
6. 更新构建配置，分别形成AArch64客户端和x86_64服务端构建命令。
7. 扩展Python解析、时钟映射、路径关联和一秒汇总。
8. 将Excel改为确认的三个工作表，同时保留原CSV和原始日志。
9. 更新回归测试和文档进度。
10. 停在“源码完成、等待目标机部署和验证”状态，等待用户下一步指令。

失败原则：

- 遥测配置失败：记录原因，继续原文件测试。
- C侧无RTT：原始值保留，比值留空。
- 单路径模式：不存在的另一条路径留空。
- 路径映射失败：保留path_id，不猜测5G1/5G2。
- JSON损坏：跳过损坏行并报告行号，其余记录继续处理。
- 服务端数据下载失败：记录远端文件路径并保留，不删除。
- Excel导出失败：保留全部原始文件并支持离线重建。
- 中断：关闭自建采集器、释放COM11，尝试下载部分数据和生成部分Excel，不切换网络状态。
