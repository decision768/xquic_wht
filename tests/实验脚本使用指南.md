# 实验脚本使用指南

## 1. 构建和部署

本实验版本沿用上一个提交节点的 CMake 构建方法和依赖配置，不需要新增构建选项。`mini/CMakeLists.txt` 已自动把新增遥测源码加入原客户端和服务端目标。

由于公共头文件、XQUIC 核心代码和 Demo 都有变化，应更新完整源码，并删除旧构建目录后重新配置和编译。不要只复制 `tests` 下的 Python 文件，也不要只单独编译 Demo 源文件。

实验版的完整构建命令见 [实验版可执行文件编译指南](实验版可执行文件编译指南.md)。该指南沿用已验证的依赖路径，并使用独立的实验构建目录。

- AArch64/SIM8810 构建目标：`netins_udp_mini_api_client`。
- Linux x86_64 构建目标：`netins_udp_mini_api_server`。
- 保持原有 `XQC_ENABLE_MINI_API=ON`、TLS、Libevent、zlog、SDK 和工具链参数。

生成后分别部署：

```text
主板 /oemdata/gx/xquic_file/netins_udp_mini_api_client
云服务器 /root/test_xquic_server/netins_udp_mini_api_server
```

部署前可分别执行：

```bash
./netins_udp_mini_api_client --version
./netins_udp_mini_api_server --version
```

正确的新程序会输出：

```text
[experiment] 实验代码V1.0 role=client api_release=6.5
[experiment] 实验代码V1.0 role=server api_release=6.5
```

如果看不到该版本信息，说明当前运行的仍是旧可执行文件，或者新文件没有成功部署到脚本配置的路径。

## 2. 控制电脑脚本目录

运行时建议保留下面的最小目录结构：

```text
实验脚本目录/
├─ 压测脚本.py
├─ benchmark_telemetry.py
├─ monitor_network.sh
└─ requirements-telemetry.txt
```

各文件作用：

- `压测脚本.py`：压测入口，控制主板、云服务器及六项 GET/POST 测试。
- `benchmark_telemetry.py`：双模块信号采集、传输遥测解析、时间关联和 Excel 导出。
- `monitor_network.sh`：由 Python 读取并通过独立主板 SSH 通道执行，采集 `rmnet_data0` 和 `usb0` 计数。
- `requirements-telemetry.txt`：Python 依赖安装清单；依赖安装完成后运行时不读取该文件。

测试样本、单元测试和改造方案不是正式运行的必需文件，可以保留用于交接和离线检查。

## 3. 远端必要文件和条件

主板需要：

```text
/oemdata/gx/xquic_file/netins_udp_mini_api_client
/oemdata/monitor_board_resource.sh
/oemapp/usr/bin/test_api
/oemdata/gx/xquic_file/download/kkk.txt       # 默认 POST 源文件
```

同时需要主板 SSH 可登录，`rmnet_data0` 和 `usb0` 存在。5G2 串口默认为 `COM11`、115200、8N1、无流控；运行前关闭占用该串口的 Xshell 窗口。

云服务器需要：

```text
/root/test_xquic_server/netins_udp_mini_api_server
/root/test_xquic_server/server.crt
/root/test_xquic_server/server.key
/root/test_xquic_server/monitor_server_memory.sh
/root/test_xquic_server/upload/1              # 默认 GET 源文件
```

服务器需要允许控制电脑通过 SSH 登录，并允许主板访问默认 QUIC UDP 端口 `18446`。如果实际路径、地址或端口不同，通过命令行参数覆盖。

## 4. 安装控制电脑依赖

在实验脚本目录执行：

```powershell
python -m pip install -r requirements-telemetry.txt
```

依赖包括 `paramiko`、`pyserial` 和 `openpyxl`。建议使用 Python 3.9 或更高版本。

密码可以在提示时输入。也可以在当前 PowerShell 会话设置环境变量，避免把密码写入脚本和命令历史：

```powershell
$env:MINI_BENCH_BOARD_PASSWORD = "主板SSH密码"
$env:MINI_BENCH_SERVER_PASSWORD = "服务器SSH密码"
$env:MINI_BENCH_SERIAL_PASSWORD = "5G2串口登录密码（没有则不设置）"
```

## 5. 运行方法

先检查参数：

```powershell
python .\压测脚本.py --help
```

使用默认配置执行一轮完整测试：

```powershell
python .\压测脚本.py --iterations 1 --direction both
```

默认顺序保持为：

```text
GET：5G1 → 聚合 → 5G2
POST：5G1 → 聚合 → 5G2
```

常用覆盖示例：

```powershell
python .\压测脚本.py `
  --iterations 3 `
  --board-ssh-host 192.168.11.1 `
  --server-ssh-host 124.70.219.194 `
  --quic-host 124.70.219.194 `
  --quic-port 18446 `
  --serial-port COM11 `
  --output-root .\log
```

可以使用以下参数单独关闭某类采集，文件传输测试仍会继续：

```text
--disable-telemetry
--disable-signal-5g1
--disable-signal-5g2
--disable-network-monitor
```

## 6. 输出和离线重建

默认结果写入实验脚本目录下的 `log`，主要产物为：

```text
log/
├─ experiment_<session>.xlsx
├─ telemetry/<session>/events.jsonl
├─ telemetry/<session>/transport/board/*.jsonl
├─ telemetry/<session>/transport/server/*.jsonl
├─ raw_client/<session>/*.stdout.log
├─ raw_client/<session>/*.stderr.log
├─ resources/<session>/
├─ stress_summary_<session>.csv
├─ aggregation_summary_get_<session>.csv
└─ aggregation_summary_post_<session>.csv
```

Excel 包含 `周期采样`、`传输汇总` 和 `配置与异常` 三张表。采集失败不会改判文件传输结果；缺失值留空并在异常表和 `events.jsonl` 中说明原因。

如果 Excel 生成失败，可离线重建：

```powershell
python .\benchmark_telemetry.py .\log\telemetry\<session>\events.jsonl `
  --output .\log\experiment_<session>_rebuilt.xlsx
```

正式实验前应先用两个 `--version` 命令确认客户端和服务端均为“实验代码V1.0”，再执行一轮短文件测试检查路径、串口和结果目录。
