已实现的行为

1. 对外新增 adaptive-v2，回调 xqc_adaptive_v2_scheduler_cb。
   adaptive 保持独立名称和回调，复用原状态机内部代码；不初始化 arrival 上下文。
   adaptive-v2 默认 off。原有至少 500 ms、最长 800 ms 的预热条件保留。

2. off 不运行预测、不启用等待 timer；shadow 预测后仍执行原选择；
   enforce 仅对服务端普通 GET 正文、BULK、两条合格路径、主路真实窗口不足、
   副路可发送的分支考虑等待。路径、指定发送、恢复、重注入、探测、FEC、
   多 STREAM、混合控制帧、HTTP/3 framing、高优先任务均保守旁路。
   已知 socket 回压、socket 故障、重绑定验证和包过滤器约束也不建立新等待。

3. GET 用途登记独立于 observer。mini 准备普通文件响应时登记 transfer、
   request_index、stream、文件范围。HTTP/3 仅在 DATA payload 写入期间标正文；
   与 framing 合并的 STREAM frame 不会被误标为纯正文。

4. 每路固定容量缓存保存有效非 app-limited 速率样本与实际 ACK 回收批次。
   ACK 缓存只接受 ACK 语境下 I 的实际下降；重复/丢失后迟到 ACK 不重复释放。
   同时间 ACK 合并，速率按 ACK 序号去重。路径 reset/destroy 清空历史。
   连续文件可继承路径历史，各 stream 的用途和等待预算分别保存。

5. 预测器只操作值副本。C、I、Z 分开保存，发送 Z 只在 I/Z 间等量转移。
   目标排在原 Z 后面；ACK 只回收快照 I，不为模拟新发 Z 虚构 ACK。
   pacing 复制 raw budget、pending、last_sent、已有 timer、突发上限和 1 ms 下限。
   窗口等待与排队同时推进，事件数、时域、整数乘加、除法和有符号收益均有边界。
   ACK 波动的 Q10/Q90 采用 nearest-rank 定义。
   模型 arrival_proxy_v1；队列近似 grouped_bytes_v1；RTT/2 是代理值。

6. 新增一次性 DEFER hint。主动等待不落入 best-candidate 兜底，
   不计入原 no_sendable/CWND 阻塞，也不增加真实 I/Z。
   包保留在原连接发送队列，以受包生命周期保护的指针和 UID 续扫，默认预算 256。
   仅存在等待或 legacy 头包保护时启用有界续扫；无等待时沿用原发送循环。
   到期头包轮转优先访问，不移动普通队列节点来续扫。
   等待结束后重新从较早的数据扫描，防止游标处的较大 offset 越过较小 offset。
   LEGACY_ONCE 保留零等待预算的同流顺序保护，直到头包进入路径队列或被清理。
   高优先级提升涉及等待流时，先撤销等待并把头包排在相关控制包前面。

7. 每连接最多一个 adaptive_arrival_wait GP timer。
   GP timer 已进入原 next_wakeup 链路；回调只标记到期，不发送或阻塞。
   正回收 ACK、pacing timeout 会让相关头包提前重检；无有用事件时不忙轮询。
   扫描未完成时也安排续扫唤醒。deadline 首次固定，重复检查不延长；
   默认 episode 5 ms、stream 总预算 20 ms，按实际经过时间结算。
   记录事件循环迟到，不承诺墙钟上恰好 5 ms 执行。
   包释放/复用、流取消、路径重置、连接退出及 mode 切换均有清理。

8. 独立 adaptive_arrival_events/schema_version=1 日志，不复用 P0 字段语义。
   输出配置、正文绑定、两路快照/预测、等待生命周期、socket attempt、
   成功发送 UID→path/pns/pn/range/time 映射及未采样汇总。
   无法得到的预测值写 null 和原因。收益比较的溢出不会变成有效的零值。
   常规预测默认每秒最多 100 条；等待生命周期不采样，丢失会标为证据不完整。
   进入等待的包即使预测详情被采样掉，也保留实际发送跟踪。
   EAGAIN/失败只有 attempt 记录，成功发送处才产生 packet_sent。
   W 误差只对实际选中且预测有效的路径计算。
   primary_recovered_send/secondary_legacy_send 的阶段是 path_queue_handoff；
   它们不能代替成功 socket 发送统计，后者看 packet_sent。

9. 公共新增 xqc_arrival_config_t，struct_size/version 独立检查；
   未向旧 xqc_conn_settings_t 或旧 scheduler callback 增加无版本参数。
   NetIns 新增调度 enum 17、配置 option 15；原 enum/option 数值保留。
   engine 配置作用于后续新连接，xqc_arrival_set_mode 可清理现有连接的等待。

10. CMake 自动生成 adaptive_arrival_source_manifest.json 和非空 source_build_id，
    包含 HEAD、dirty 及实际源码 SHA256。直接绕过构建标识编译时会注明 unverified。
    正式部署还须保留完整编译命令、依赖版本和实际运行二进制 SHA256。
    压测脚本记录 source ID、/proc/PID/exe 哈希、requested/resolved 名称和 mode。

实现近似与后续验收

速率仍需默认至少 8 个有效样本、跨度一条 SRTT、BBR full_bw、新鲜度满足。
只有 16 个样本的缓存可能无法覆盖某些高 RTT/密 ACK 条件，策略会正常旁路。
不使用 CWND/SRTT 或 1024 B/s 补成“高置信”数据。
本轮只接受本库原版 BBR 回调的身份；BBR2、其他 CC 或自定义等价接口不会默认启用等待。
分组 Z、固定短期 C、不预测未来其他包竞争及不虚构新 Z 的 ACK 都是模型限制。
RTT/2 不是单程实测；收益门槛不是统计置信界；shadow 不证明换路后 FCT 会改善。

本次 64 位测试中 arrival runtime 为 12024 B/连接，stream 元数据为 424 B/流。
packet_out 当前为 600 B。独立日志复用了既有异步 writer，记录队列本身约 16 MiB/连接，
另有线程和文件缓冲开销；正式性能实验必须同时评估 CPU、内存和日志开销。

必要的共有修复单独保留：xqc_on_packets_send_burst 中
XQC_CAN_IN_FLIGHT 的括号原先错误地包含 pacing_on 布尔判断，导致 ACK-only 批量包扣 pacing。
本次改为和单包路径相同的帧类型判断，并有 ACK-only 批量回归。
它作用于同一版本所有算法，不能把该修复的效果算作新策略收益。
