# P0 可靠采集修复与复验

日期：2026-11-03。此说明对应已批准的 P0 最小修复方案。

## 已完成与未完成

已实现写入链路、观测时钟、任务检查点、Python任务级验收及图表修复，并完成下述本地检查。本机不是实际双端测试环境，尚未完成实际设备/服务器重新构建部署、12项真实文件传输验收及 observer 开/关性能对照；不得把本地合成/线程验证写成真实路测通过。

客户端、服务端的文件收发、原有分片与并发、校验、算法选择、拥塞控制、重注入、adaptive控制周期及旧吞吐口径没有改动。观测仍有CPU、内存和IO开销，需要实际对照测量。业务完成后新增控制机验收等待；观测异常时不主动中断当前业务，保存业务结果后停止后续项目。

GET旧指标仍为 `first_body_to_last_body`，POST仍为 `app_submit_not_remote_receive`。新增接收端正文FCT和客户端确认耗时单列。

## 实现要点

- writer保留64槽、每条32 KiB的有界存储，普通数据最多占62槽，预留控制容量。单一engine生产者与写线程消费者通过原子发布和semaphore协作，不再因互斥锁瞬时竞争直接丢弃。
- 按实际长度复制；写线程在256 KiB、100 ms、封段或任务结束时刷新，不再每条fflush。100 ms是正常调度下的刷新目标，不是故障/线程失调时的硬实时承诺。
- 队列满、过长记录和写入故障会记录错误，绝不无限扩容、等待磁盘或伪造零丢失。正常验收必须dropped=0；异常场景应判为INVALID。
- END与最终流记录之后提交FIFO检查点。写线程封存两类分段，再发布 `PREFIX.checkpoint.NNNNNN.json`；凭据包含attempt/连接、累计written、两类最终序号、封存分段数、writer错误/丢弃及boot_id。控制消息不计入JSONL记录序号。
- 检查点计数是同一writer生命周期内截至该点的累计量，不是单次任务独占记录数。检查点不可覆盖；连接关闭仍生成最终 `.health.json`。
- 新增 `observer_revision=2`、`clock_domain=CLOCK_MONOTONIC` 和 `task_checkpoint=true` 能力。transport schema v2与event schema v1兼容扩展；公共API v1结构未改。
- 新增时钟只服务观测。XQUIC全局时钟、原吞吐计时、原控制与决策分支不变；时钟失败不回退墙上时间。
- 以attach时已存在CLI双向流的最大ID判定覆盖缺口，不再比较不同时间域的create_time。已结束流保留最终记录，不反复生成结束后的周期流快照。
- 正式入口从脚本自身目录加载依赖，防止优先导入tests中的旧副本。未移动、删除或同步旧目录。
- 每项先写原有 `attempts.jsonl` 业务结果，再等待检查点；观测结果单独保存在 `observability/attempt_validation.jsonl`、manifest和最终results。观测异常不改业务success字段。
- 默认等待检查点发布15秒（`--observer-checkpoint-timeout-s`可调整）；该时间与随后原始日志的下载耗时分开。缺少新能力或必需控制机依赖时，在文件传输前停止。
- `hol_valid`与`window_valid`分别反映接收侧和发送侧可用性；新增 `observation_valid` 要求二者及完成阶段等全部通过。任何整体验收失败都会停止后续测试。未通过的数值保留供排障，不升级成有效测量。
- 严格检查文件哈希、序号/计数、START/END、检查点、流映射/范围、最终正文合计、HoL episode与累计量、正文时间边界及发送路径有效时间覆盖。
- 窗口覆盖按实际ACTIVE路径的观测寿命计算，目标至少99%；超过2.5个采样周期的间隔记为未知，不补零。零有效CWND的比例保持null，超过100%的占用不截断。
- 跨端对齐必须先验证时钟域及本地锚点一致性；误差界按双端保守相加。超过100 ms明确标记COARSE，不宣称100 ms内先后。旧日志缺少时钟证据时不精确叠图。
- 缺失绑定时，可依据自包含的流结束记录恢复正文统计，但仍报告缺失事件并保持无效，不能补造丢失的episode。

## 本地验证结果

- 34项现有Python回归及5个subtests通过。另1项旧用例固定读取已改名的 `test_wht/副本改进版.py`，与当前用户目录状态不兼容，因此排除；已对正式入口补做等价的12项计划检查。
- 31项针对性Python检查通过：正常GET/POST、不依赖连接关闭即完成检查点验收、25流/100 MiB、丢记录、缺START/END/周期记录、错误计数/类型/标识、boot不匹配、缺分段、绑定恢复与冲突、正文不足、完成阶段缺失、窗口公式错误、时钟域错误/跳变、零窗口、HoL累计不一致、回收超时/哈希失败、预检和禁用模式等。
- 本机实际执行writer线程测试：10,000条JSON记录全部写入、两类序号各连续5,000条、两份不可变检查点和最终health计数一致，正常场景零丢失；覆盖环形回绕、控制槽、过长记录、空闲刷新、立即关闭排空和写入失败。
- C时钟注入测试：墙上时间回退5秒，20 ms HoL积分仍准确；时钟错误返回失败标记，不回退墙上时间。原独立HoL区间测试及10,000次随机对照通过。
- 9个变更C编译单元分别通过x86_64-linux-musl、aarch64-linux-musl对象编译；writer、transport observer、Mini observer通过Clang Static Analyzer。验证命令处理了原有未使用变量/参数类告警及Zig对原编译日期宏的可复现限制，没有为此修改业务源码。
- Python语义静态检查、语法检查、差异空白检查通过。10个原业务计划/解析/汇总函数经AST对比未变，调度器改动只涉及新增观测时间及其失败标记。
- Excel和PNG合成产物生成通过，已目视检查四联图：0.6秒样例正确显示0.6秒横轴，120 ms合计误差明确标COARSE。合成图不是真实测量。
- 历史11月3日压缩包仍可读取；缺绑定的minrtt 5G1 GET可恢复为25流/100 MiB，但其原有丢记录和时钟问题仍保留为无效。

C线程执行使用本机Windows目标的winpthreads；Linux双架构编译使用临时头文件/工具链。它们不能代替实际设备的Linux链接与运行测试。

## 实际环境部署与复验

### 需要同步什么

1. 将本清单中的C源码、头文件同步至实际构建环境，使用原有CMake配置重新编译客户端和服务端；不要只更新Python。
2. 部署新二进制到原有配置所指目录。新时钟头文件必须同时同步；无需改端口、业务根目录或证书配置。
3. 控制机同步正式入口和同目录 `roadtest_observability.py`，并保留原有同目录 `benchmark_telemetry.py`、`requirements-telemetry.txt`。后两份本轮没有改动，但仍是运行依赖。
4. 所有目录仍来自脚本位置和现有参数；以下命令以项目根目录为工作目录，不包含本机绝对路径。

### 开始前

在实际客户端、服务端各自二进制目录运行对应命令：

```bash
./netins_udp_mini_api_client --telemetry-capabilities
./netins_udp_mini_api_client --observer-clock
```

服务端用 `netins_udp_mini_api_server` 替换命令中的客户端名称。应返回revision 2、CLOCK_MONOTONIC、task_checkpoint true；clock输出还应包含正整数单调时间、实时时间及有效boot_id。不能只看api_release=6.5判断已部署修复。

控制机安装原有运行依赖：

```powershell
python -m pip install -r test_wht/requirements-telemetry.txt
```

先只生成计划，确认实际地址、路径和测试矩阵：

```powershell
python "test_wht/压测（路测+裘博指标）.py" --schedulers adaptive,minrtt --direction both --iterations 1 --verify-sha256 --dry-run
```

再保留实际环境原有SSH、目录和接口配置，移除 `--dry-run` 开始一轮。使用既有100 MiB GET/POST源文件；不要依靠修改前脚本的默认方向猜测本次矩阵。

### 通过门槛

- 12项业务完成，文件SHA256一致；日志SHA256正确与文件内容SHA256正确是两件不同的事。
- 双端每项检查点存在，writer_error=0、dropped_records=0；两类序号无缺口，封存分段及记录数一致。
- START/END、流绑定与最终流记录齐全；文件range不重叠且覆盖全部100 MiB，接收正文合计正确。
- HoL累计、episode、时间边界一致；发送路径有效覆盖至少99%；summary中的hol_valid/window_valid/observation_valid均为True。
- Excel、PNG、CSV成功生成；时间轴与实际时长一致，误差标识明确；minrtt不伪造固定主副角色。
- 发现观测INVALID时，当前业务结果已在attempts/results中保存，后续项目未开始；保留端点原始日志供排查。

本轮没有修改无线/网卡采集默认状态，也没有加入P1。完成上述验收后，再用同样配置加 `--disable-observer` 做开/关对照，比较CPU、内存、日志量、采样迟到、吞吐及FCT；不要将一次对照的无线波动直接认定为观测开销。
