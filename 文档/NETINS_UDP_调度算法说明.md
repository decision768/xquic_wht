# NetIns UDP 多路径调度算法说明


## 1. Adaptive：根据综合网络表现动态调整的调度策略

### 1.1 算法定位

Adaptive 是一种面向多链路综合利用的自适应调度策略。它不只比较某一个固定指标，而是结合链路的数据交付能力、时延变化、排队情况、丢包表现和当前发送能力，持续评估各条链路的实际传输效果。

它的主要目标是在网络状态不断变化的情况下，找到当前综合表现较好的主路径，同时保留对其他链路的观察和利用能力。当链路质量发生变化时，调度比例和主路径也可以随之调整。

### 1.2 核心概念

Adaptive 会关注链路的“有效交付能力”，即一段时间内真正送达对端的数据速率，而不只是理论带宽。算法还会观察 SRTT 及其相对变化：如果当前时延明显高于该链路此前的较低水平，通常意味着链路可能出现排队或负载增加。

这些信息会形成链路的综合评价。交付能力较强、时延和排队情况较好、近期丢包较少的链路，通常会获得更高评价。该评价用于确定主路径，也用于判断其他链路是否值得承担更多数据。

### 1.3 调度方式

当存在多条可用链路时，Adaptive 首先经历一个短暂的评估阶段，让各条链路都有机会发送和交付一定数据，从而获得可比较的实际表现。评估完成后，算法选择综合评价较高的链路作为主路径。

进入稳定传输阶段后，大部分数据通常由主路径承担。同时，算法会给其他可用链路保留一定比例的探测流量，用于持续了解它们的最新状态。这个比例不是固定不变的：如果辅助链路表现良好且整体传输效果没有下降，系统可以逐步增加其使用比例；如果辅助链路排队加重或使用后整体效果下降，则会减少相应比例。

当另一条链路持续表现得明显更好时，Adaptive 才会考虑更换主路径。它不会因为一次瞬时波动立即频繁切换。当主路径暂时不具备发送条件时，只要其他链路可用，数据也可以通过其他链路继续发送。

### 1.4 主要特点与价值

Adaptive 的特点是兼顾“选择当前较好的路径”和“持续发现网络变化”。它既不会只依据连接开始时的结果长期固定路径，也不会为了平均分配而忽略链路之间的实际差异。

对于使用者而言，算法可以根据实时网络表现自动调整主次关系和流量比例，减少人工配置固定分流比例的需要。在链路带宽、时延和负载不断变化时，这种方式有助于保持较好的综合传输效率，并在某条链路暂时受限时利用其他可用链路。

Adaptive 的实际调度结果可能随时间变化，这是算法主动适应网络状态的表现。一次测试中看到的路径占比，不应直接视为永久固定比例。


### 1.6 小结

Adaptive 通过短暂评估建立主路径，再根据交付能力、时延、排队和丢包等综合表现动态调整主路径与辅助链路使用比例。它体现的是持续评估、适度探测和随网络变化自动调整的综合调度思路。

## 2. MinRTT：基于链路时延的优先选择策略

### 2.1 算法定位

MinRTT 是一种面向多链路传输的时延优先调度策略。当设备同时通过多条网络链路与服务器通信时，各条链路的响应速度可能不同。MinRTT 会结合链路当前状态和时延表现，为待发送数据选择响应相对更快的可用链路。

它的主要目标不是平均使用每一条链路，而是让数据优先通过当前时延较低、具备发送条件的链路传输，从而改善业务的响应速度和等待体验。

### 2.2 核心概念

RTT 是 Round-Trip Time 的缩写，即“往返时延”，表示数据从发送端到达对端，再由响应返回发送端所经历的时间。RTT 越低，通常说明该链路当前的响应速度越快。

实际网络可能受到信号变化、负载波动和临时排队等因素影响，单次 RTT 测量可能存在较大波动。因此，当前版本主要参考 SRTT，即“平滑往返时延”。SRTT 综合链路近期的多次测量结果，可以减少偶然波动对调度判断的影响，更稳定地反映链路当前的时延水平。

### 2.3 调度方式

MinRTT 在选择发送路径时，首先检查各条链路是否处于活动和可使用状态。已经关闭、被冻结或者当前不具备发送条件的链路，不会作为本次调度的首选。

在优先级相同且能够发送数据的候选链路中，算法比较各条链路的 SRTT，优先选择数值较低的链路。可以将其理解为：面对多条可通行的道路，系统优先选择当前预计往返用时较短的一条。

这种选择不是连接建立时的一次性决定。随着网络环境变化，各条链路的 SRTT 和可用状态也会持续变化。后续数据发送时，MinRTT 会根据更新后的链路状态重新判断。如果原本优选的链路暂时不能发送，系统会选择其他符合条件的链路继续工作。

### 2.4 主要特点与价值

MinRTT 的选择依据明确，调度结果容易理解：在链路状态和优先级相同的情况下，响应更快的链路通常会承担更多数据传输。

这种策略减少了用户手工比较和切换网络接口的需要。当不同链路之间存在较明显的时延差异时，数据会更倾向于通过低时延链路发送，有助于降低交互等待感。同时，链路状态发生变化后，调度结果也会随之调整，而不是永久固定在最初选择的路径上。

需要注意的是，MinRTT 表示“以低时延为主要选择方向”，实际传输效果仍会受到网络质量、带宽、丢包、对端处理能力和链路可用状态等因素影响。


### 2.6 小结

MinRTT 先确认链路可用并具备发送条件，再优先选择当前 SRTT 较低的路径，并随着网络状态变化持续更新后续数据的发送选择。整体而言，它体现的是清晰、直观的低时延优先思路。

## 3. Backup：主路径锁定与故障接替策略

### 3.1 算法定位

Backup 是一种强调主用与备用关系的调度策略。它会从多条可用链路中选择一条作为主路径；主路径确定后，常规数据优先并持续通过主路径发送，其他链路主要承担备用角色。

它的主要目标是保持传输路径相对稳定，并在主路径失去可用状态时，由其他可用链路接替传输。与持续在多条链路之间调整流量比例的方式相比，Backup 更强调明确的主备关系。

### 3.2 核心概念

当前版本的 Backup 采用“自动评估后锁定主路径”的方式，并不是简单地把第一个接口永久指定为主路径。连接初期，算法会让多条可用链路参与短暂评估，观察各链路实际交付的数据量、交付速率、带宽估计和 SRTT。

主路径主要依据传输能力选择；当多条链路的传输能力接近时，时延较低的链路更有机会成为主路径。完成选择后，算法锁定该路径，其他路径进入备用角色。

### 3.3 调度方式

在初始评估阶段，各条可用链路都会获得一定发送机会，以便系统取得基本的实际传输样本。评估结束后，综合传输表现较好的链路被锁定为主路径。

主路径保持活动和可用时，后续常规数据继续由它承担。即使主路径只是暂时达到当前发送上限，Backup 也不会立即把普通流量分散到备用链路，而是等待主路径恢复发送能力，以维持严格、稳定的主备关系。

当主路径关闭、被冻结或不再处于可用状态时，算法进入故障接替过程，从其他具备发送条件的链路中选择路径继续传输。如果原主路径随后恢复可用，调度会重新回到已经锁定的主路径。

### 3.4 主要特点与价值

Backup 的主要特点是主路径明确、常规传输路径稳定、备用链路职责清晰。用户可以较容易地从日志和路径字节统计中判断哪条链路承担主要流量，以及是否发生过备用链路接替。

这种策略减少了正常状态下在多条链路之间频繁改变数据分配的情况，使路径行为更容易预测。当主路径真正失去可用状态时，备用链路可以接替发送，为多网络连接提供连续传输能力。实际切换时间和业务感受仍会受到故障检测速度、备用链路状态及网络环境影响。


### 3.6 小结

Backup 先通过短暂评估自动选出并锁定主路径，正常情况下由主路径持续承担数据发送；只有主路径失去可用状态时，其他路径才主要发挥接替作用。它体现的是路径稳定、主备清晰的调度思路。

## 4. 三种调度策略的关系与选择参考

MinRTT、Adaptive 和 Backup 都只在当前可用并符合发送条件的链路范围内工作，但三者关注的目标和使用链路的方式不同。

| 对比维度 | MinRTT | Adaptive | Backup |
|---|---|---|---|
| 主要目标 | 优先使用当前往返时延较低的链路 | 根据多项网络表现动态获得较好的综合传输效果 | 建立稳定的主备关系，并在主路径失效时接替 |
| 路径使用方式 | 每次调度时倾向选择 SRTT 较低的可用链路 | 以主路径承担主要流量，并动态调整辅助链路的探测和使用比例 | 评估后锁定主路径，正常流量集中在主路径，其他路径主要备用 |
| 用户感知 | 路径选择与时延变化关系直观，数据更倾向低时延链路 | 路径占比会随网络状态调整，综合利用方式更灵活 | 正常状态下路径相对固定，故障时可观察到备用链路接替 |
| 选择侧重点 | 更关注响应速度和低时延导向 | 更关注变化网络下的综合表现和多链路利用 | 更关注主路径稳定性及备用链路保障 |

选择调度算法时，可以首先明确业务最关注的目标：希望系统持续综合评估网络状态并动态利用多条链路，可选择 Adaptive；希望数据优先通过响应更快的链路，可选择 MinRTT；希望保持明确、稳定的主备关系，可选择 Backup。
