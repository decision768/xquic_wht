# P0 被动观测：实施与验证说明

2026-11-02。适用入口：`test_wht/副本改进版.py`；`tests/副本改进版.py`同步相同改动。

本次是代码实现与本地检查，尚未部署双端二进制，未运行真实设备 GET/POST 路测，也未测定 observer 的实际开销。图表测试使用合成数据，不是路测结果。

## 保留的测试内容

保留 GET/POST、5G1/5G2/Agg、发送端算法轮换、预热排除、重试与冷却、资源监控、原有完整性检查及吞吐/成功率/聚合率统计。10 个原有计划、解析和汇总函数经 AST 对照未改变。

GET 旧口径仍为 `first_body_to_last_body`；POST 仍为 `app_submit_not_remote_receive`。新增接收端正文完成、写队列排空、fsync 和客户端确认时间单独保存，不能用新增阶段改变旧吞吐分母。

## 新增观测与字段口径

| 范围 | 新增内容 |
|---|---|
| STREAM 接收 | C/N、唯一区间并集 B、连续可读未读取量 A；pending/exposed 累计时间；B·μs 面积；累计/区间峰值；episode 开始、结束、时长、峰值、删失 |
| 文件任务 | 绑定目标流数、流时间之和、episode 时间并集、any-stream 比例、正文累计量/首末时间；连接 sum_B、面积和事件峰值 |
| 发送窗口 | 同一事件循环读取 raw/effective CWND、I、Z、占用与剩余量、SRTT；参考 1200 B 包资格；真实调度检查另保留实际包大小、检查时间和阻塞理由 |
| 流控 | 连接及流的发送上限、偏移和派生剩余额度；连接额度明确是共享的 |
| 主副路 | adaptive phase、primary/secondary、目标份额、role_epoch；角色/控制变化事件携带发送计数基线 |
| 调度与发送 | 8 类互斥 pick reason 次数/selected 字节；重注入交叉字节；四种可发组合检查次数；两类窗口回退次数/字节；无路可发调用数；逐路径实际 QUIC 包发送/重传/重注入/交付计数 |
| 本地消费 | GET 写队列字节/深度、写队列排空与 fsync 阶段；POST 写入累计耗时、次数和 fsync 阶段 |
| 数据质量 | 能力探测、双端二进制哈希、脱敏启动参数、时钟探测/误差/漂移、序号缺口、SHA256、缺 START/END、writer 健康、溢出、未绑定和删失 |

HoL 为目标请求流的 STREAM 字节口径，包含 H3 framing，不含 QPACK 等待；正文数量另计。B 不包含未收到的洞，不使用最高 offset 与 C 的差值冒充。普通消费积压不计为网络重排 HoL。

窗口比例为 I/Ceff、Z/Ceff、(I+Z)/Ceff。Ceff=0 或字段缺失时比例为空，超过 100% 的值保留。占用时间统计使用实际间隔加权估计，超过 2.5 个输出周期的断档排除并记录覆盖率。

`wire_sent_bytes` 是编码 QUIC 包字节，不是完整 IP/UDP 字节。STREAM/DATAGRAM 包按整包计数，含重复发送。selected 字节与实际发送字节分开；实际副路占比按角色 epoch 的物理路径发送增量计算。

`evaluation_block_reason`：0=无 CWND 阻塞，1=真实在途，2=调度预留；必须同时看 `evaluation_check_cwnd` 和检查时间。它不能替代当前快照的 I/Z/CWND。

在途包数从带 IN_FLIGHT 标志的未确认队列只读统计；单次遍历超过 262144 个节点时输出 null，避免无界观测工作。

## 接口与日志

公共 API v1 结构布局及全局 API 版本未改变。新增独立 `netins_udp_observer_config_t`、`NETINS_UDP_OPT_OBSERVER_V2` 和底层只读观测入口。

双端新增 CLI：

```text
--telemetry-capabilities
--observer-clock
--telemetry-output PREFIX
--attempt-id TOKEN
--telemetry-interval-ms N
```

新增 `transport` schema v2 和独立 `observer_events` schema v1。Python 同时接受历史 transport v1，历史没有的新指标保持缺失。

日志线程只接收已复制的 JSON 记录，不访问 conn/stream 裸指针。队列有界，满或竞争时记录丢弃并使观测失效，不阻塞调度热路径。每 4 MiB 在完整记录边界封存分段；`.active` 是尚未封存文件，`.health.json` 保存 writer 最终状态和 boot_id。完成或关闭时排空队列。

控制机按 attempt 取回封存分段；结束时抢救 `.active` 并标记不完整。每份下载校验 SHA256，保留原始字节、记录远端补取目录，不自动删除远端观测日志。为减少 Windows 长路径问题，本地分段前缀使用哈希，原文件名和远端完整路径保存在 manifest。

服务器每次启动使用独立运行日志，stdout/stderr 一同保存，避免算法重启覆盖上一份日志。归档失败时保留对应远端状态目录。

`conn_uid` 是本端生命周期 ID；两端按合法 attempt 绑定。路径不按数组序号猜测网卡身份：接口无充分证据时保持 UNKNOWN。NAT 下服务器物理路径可能无法自动映射到 5G1/5G2，原始映射和端点地址保留供核验。

压测入口每次尝试使用唯一 run_tag。重复使用同一 attempt ID 发起多次文件传输会标记 invalid；请勿用一个 `--attempt-id` 配合 Demo 的 `--repeat > 1` 生成可比较的 P0 数据。底层允许不同合法 attempt 的顺序绑定；同连接的新任务绑定前聚合覆盖不足会显式标记，不升级为完整测量。

## 控制机使用

先按仓库现有文件传输编译指南重新构建并部署服务器与设备端配套二进制。控制机依赖：

```powershell
python -m pip install -r tests/requirements-telemetry.txt
```

正式运行仍使用原入口及原有配置，P0 默认启用、输出周期 100 ms：

```powershell
python test_wht/副本改进版.py --observer-interval-ms 100
```

`--disable-observer` 可关闭新增传输观测，供开销对照。旧二进制不支持时，业务测试继续，观测标为 UNSUPPORTED，不把零值当测量。

可用 `--observer-radio` / `--observer-network` 显式启用已有无线/网卡采集，相关串口/查询参数沿用 `benchmark_telemetry.py`。默认不启动这些额外采集器。无线原始查询时间/状态留在独立 telemetry 事件中，不通过前向填充伪造样本。

新增结果在实验目录的 `observability/`：

```text
manifest.json
raw/board/、raw/server/
server_logs/
path_windows.csv
rx_hol_streams.csv
rx_hol_episodes.csv
transfer_observability_summary.csv
observer_health.csv
observability.xlsx
plots/<attempt>.png
artifact_status.json
```

CSV/Excel/PNG 是派生结果；原始日志及 manifest 是事实来源。Excel/绘图依赖故障写入 artifact_status，不修改业务成功状态。大整数 CSV 保持十进制整数；Excel 超过 2^53 的整数以文本保存。

离线重建 CSV：

```powershell
python tests/roadtest_observability.py "实验目录/observability"
```

检查结果时先看双端 START/END、序号、writer health、哈希及覆盖率，再解释曲线。GET 的发送窗口在服务器、HoL 在设备；POST 相反。接收侧和发送侧分别有有效性状态，跨端时钟失败不冒充精确对齐。

## 已执行的验证与边界

- Python：35 项测试及 5 个 subtests 通过；语义静态检查、字节码编译通过；CSV/Excel/四联图生成通过，并检查合成图布局。
- C：16 个变更编译单元分别通过 x86_64-linux-musl 与 aarch64-linux-musl 编译检查，包含格式串错误检查。
- 新增核心观测、JSON writer、Mini timer 三个单元通过 Clang Static Analyzer，无诊断；分析发现的 fflush/fclose 错误码保留问题已修复。
- 独立 C 区间测试在本机编译运行，覆盖顺序、缺口、重叠/重复、pending/exposed、短 episode、溢出，并用字节位图 oracle 对照 10000 次随机更新。
- 两份脚本保持一致；10 个原有编排/解析/汇总函数经 AST 对照未改变；实际执行 dry-run，仅生成原有 12 项测试计划，未连接 SSH。

C 检查使用独立临时工具链与第三方头文件，未完成正式双端依赖下的完整链接/部署。尚待实际环境验证 GET/POST 双端日志、网络中断补取、磁盘/队列故障和 observer 开关开销。静态检查通过不能保证不存在运行时问题。

P1 的每字节等待分位数、精确窗口事件积分、首次正文路径归因、文件连续前缀和跨 lane 重排均未加入。
